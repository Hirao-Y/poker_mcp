# 子孫核種の自動管理（v1.4.0）

## 概要

線源のインベントリに親核種を指定すると、子孫核種が自動的に生成されます。
親を更新・削除すると、それに紐づく子孫核種も自動的に追随します。

生成された子孫核種は `x_meta.derived_from` を持つ「派生エントリ」として記録され、
ユーザが明示的に入力したエントリとは区別して管理されます。

## 発火タイミング

`poker_proposeSource` および `poker_updateSource` の実行時です。
以前のバージョンでは `poker_executeCalculation` の実行時に確認を求めて
計算を中断していましたが、v1.4.0 で廃止しました。

計算時に中断する方式には2つの問題がありました。第一に、モデル構築を
すべて終えた最後の段階で計算が失敗するため、原因の特定が困難でした。
第二に、親核種を削除しても子孫核種が残るという伝播漏れを解決できませんでした。

## 再計算の規則

線源が変更されるたびに、以下が実行されます。

1. `x_meta.derived_from` を持つエントリをすべて破棄する
2. ユーザ指定エントリを親として、子孫核種を再生成する
3. 生成物をさらに親として、次世代を展開する（最大8世代）

「全消し再構築」方式のため、差分追跡のロジックが不要です。
親の放射能を変更すれば子孫核種も比例して変わり、親を削除すれば
子孫核種も消えます。線源ごと削除した場合も同様です。

## エントリの3状態

| 状態 | 記録場所 | 再計算時の扱い |
|---|---|---|
| 自動生成された | `inventory` の要素（`x_meta` あり） | 毎回破棄して再生成 |
| ユーザが入力した | `inventory` の要素（`x_meta` なし） | 一切変更しない |
| 明示的に除外した | `source.x_meta.excluded_daughters` | 生成しない |

ユーザ指定エントリは自動生成より優先されます。同じ核種をユーザが
自分で入力している場合、派生エントリは追加されません。

## 平衡モデル

子孫核種の放射能は、親娘の半減期の比によって決まります。

| 条件 | 平衡型 | 放射能 |
|---|---|---|
| T_親 > 100 × T_娘 | 永続平衡 | A_娘 = A_親 × 分岐比 |
| T_親 > T_娘 | 過渡平衡 | A_娘 = A_親 × 分岐比 / (1 − T_娘/T_親) |
| T_親 ≤ T_娘 | 平衡なし | **生成しない**（警告を出力） |

平衡が成立しない場合、冷却時間の情報なしには子孫核種の放射能を
決定できません。推定値を入れると誤った線量評価につながるため、
生成せずに警告を返します。必要であれば、その核種をユーザが
明示的に指定してください。

実例：

```
Cs137 → Ba137m  : 30.17y / 2.552m → 永続平衡、係数 0.9440
Sr90  → Y90     : 28.8y  / 64.0h  → 永続平衡、係数 1.0000
Mo99  → Tc99m   : 2.75d  / 6.01h  → 過渡平衡、係数 0.9654
Pr144 → Nd144   : 17.3m  / 2.29e15y → 平衡なし、生成せず警告
```

## 除外の管理

除外は線源ごとに `x_meta.excluded_daughters` へ記録されます。

```yaml
source:
  - name: Generator_Column
    x_meta:
      excluded_daughters:
        - Tc99m        # 溶出直後のため過渡平衡が未成立
    inventory:
      - nuclide: Mo99
        radioactivity: 3.7e10
```

記録が永続化されるため、以後 `updateSource` で親を何度変更しても
除外した子孫核種は復活しません。除外を解除するには
`action="confirm"` を実行します。

除外が必要になる典型例は次のとおりです。

- **ジェネレータの溶出直後** — Tc99m が取り出された直後は平衡が未成立
- **非密封の Ra226 線源** — 娘の Rn222 は気体のため開放系では散逸する
- **核種を別線源に分離している場合** — 子孫核種の検出は線源単位で走るため、
  隣の線源に同じ核種があっても検知できない

## poker_confirmDaughterNuclides

子孫核種の生成そのものは自動化されたため、このツールの役割は
「生成結果の事後調整」に変わりました。

| action | 動作 |
|---|---|
| `check` | 派生核種・ユーザ指定核種・除外設定の一覧を表示 |
| `reject` | 対象線源で除外登録する（`source_name` 必須） |
| `confirm` | 除外を解除し、次回の再計算で復活させる |
| `confirm_with_modifications` | 放射能を手動指定する（同時に除外登録される） |

`nuclides` 引数で核種を個別に指定できます。省略時は、`reject` なら
生成済みの派生核種すべて、`confirm` なら除外設定すべてが対象になります。

```
poker_confirmDaughterNuclides action="reject"
  source_name="Generator_Column" nuclides=["Tc99m"]
```

### 除外は線源ごと

v1.3.0 以前の `reject` は、グローバルフラグ
`daughterNuclideCheckDisabled` を立てる実装でした。このため、ある線源で
一度拒否すると、セッション終了まで**全線源**の子孫核種検出が無効に
なっていました。v1.4.0 で線源ごとの管理に修正しています。

## x_meta について

`x_meta` は POKER の線量計算に一切使用されない注釈ノードです。
POKER 側は受理して読み捨てます。MCP が出自情報を保持するために
使用します。

許可されているのは `source` 直下と `inventory` 要素直下の2箇所のみです。

```yaml
source:
  - name: SpentFuel
    x_meta:
      excluded_daughters: [Tc99m]
    inventory:
      - nuclide: Cs137
        radioactivity: 2.0e16
      - nuclide: Ba137m
        radioactivity: 1.888e16
        x_meta:
          derived_from: Cs137
          equilibrium: secular_equilibrium
```

POKER のパーサは全階層でホワイトリスト検証を行うため、これ以外の
位置に `x_meta` を置くと入力が拒否されます。
