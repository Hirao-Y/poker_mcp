# CAD 連携レイトレース（tools/）

FreeCAD で作ったソリッドモデルをそのまま遮蔽体系として扱うための実験的ツール群です。`tools/` 配下にあり、MCP サーバ本体とは独立して動作します。

## 狙い

POKER に CAD モデルを読み込ませる代わりに、**FreeCAD 側で線源点→検出器の直線を追跡し、通過した材質と厚さの並びを POKER に渡す**という構成です。STEP のような中間フォーマットを介さず、CSG プリミティブで表現し直す作業も不要になります。

3 つの用途があります。

1. **経路注入**（`gen_paths.py`）— 全レイの層構成を `.paths` ファイルに書き出す。POKER 側の受け入れ改造が前提。
2. **簡易化の監査**（`audit_mfp.py`）— 詳細 B-rep モデルと、POKER プリミティブで表現できる簡易モデルの差を線量影響として定量化する。POKER の改造は不要で、今すぐ使える。
3. **対話的な経路確認**（`ray_trace_tri.py`）— 任意の 2 点間が通る材質と厚さを調べる。

## 構成

| ファイル | 役割 |
|---|---|
| `ray_trace_tri.py` | レイトレーサ本体。テッセレーション＋BVH＋numpy バッチ交差 |
| `poker_lib.py` | POKER の `LIB` 読み込み（組成・減衰係数・ビルドアップ可用性） |
| `gen_paths.py` | 線源×検出器の全レイをトレースし `.paths` を生成 |
| `audit_mfp.py` | 詳細モデルと簡易モデルの Δmfp を符号付きで比較 |
| `make_cask_models.py` | 監査の動作確認用キャスクモデル（フィレット有無の 2 種）を生成 |
| `spec_cask.json` / `spec_audit.json` | 実行設定の例 |

## 動作環境

FreeCAD 1.1 に同梱の Python（3.11）と numpy を使います。**GUI の MCP ブリッジ経由では実行しないでください。** 数万レイのトレースは GUI スレッドを数十秒占有し、RPC がタイムアウトしたうえブリッジの標準出力が壊れます。ヘッドレスで起動します。

```powershell
& "C:\Program Files\FreeCAD 1.1\bin\freecadcmd.exe" -c `
  "import sys; sys.path.insert(0, r'<repo>\tools'); import gen_paths; gen_paths.main(r'<spec>.json')"
```

`freecadcmd` はスクリプト以降の引数を「開くファイル」と解釈するため、`-c` で呼び出します。

## モデル側の約束

- 各ソリッドに文字列プロパティ **`PokerMaterial`** を持たせ、POKER の材料名を入れます。無い場合はオブジェクトのラベルが使われます。
- 単位は FreeCAD mm、POKER cm。`unit_scale`（既定 0.1）で換算します。
- ブーリアン演算の元形状は非表示のままドキュメントに残るため、既定では**可視オブジェクトのみ**を対象にします。二重計上を避けるためです。

## レイトレーサの仕様

ソリッドを `Shape.tessellate(deviation)` で三角形化し、BVH（既定リーフサイズ 4）を張って Möller–Trumbore を numpy でバッチ処理します。交差点を距離順に並べ、各ソリッドの内外フラグを反転させながら区間ごとの材質を決めます。

実装上の要点が 3 つあります。

- **始点が線源内部にある場合**があるため、レイを場面外まで後退させて初期の内外状態を実測し、あとで始点にクリップします。
- **テッセレーションの継ぎ目**をレイが走ると同一位置で三角形 2 枚に当たり、内外フラグが 2 回反転して打ち消します。同一位置の重複ヒットは 1 オブジェクトにつき 1 回だけ反転させます。
- **区間の重なり**（複数ソリッドが同じ区間を占有）は自動解決せず、バウンディングボックスの小さい方を採用したうえで件数を報告します。

### 精度

テッセレーション偏差の既定は **0.5 mm**。鉛の 0.05 mfp に相当する 0.75 mm より細かく取っています。OCC ブーリアンによる参照実装と 200 レイで突き合わせた結果、材質別の総厚さの差は **0.02% 以内**でした。

### 速度

同心円筒殻のような体系では AABB が互いに大きく重なり、全交差を取る必要から早期打ち切りも使えないため、枝刈りが効きにくくなります。

キャスクモデル（三角形 20,370 枚）の実測は **約 290 µs/レイ**。線源分割 3,840 点 × 検出器 15 点 = 57,600 レイで **約 17 秒**です。

規模の目安として、応答時間 5 分を上限とするなら **約 100 万レイ**が現実的な上限になります。線源分割 3,840 点なら検出器 267 点まで。蓋面の 2D グリッド 16×16 = 256 点は約 4 分で収まりますが、3D グリッド 25³ = 15,625 点は 4.9 時間となり成立しません。**経路注入は既存の CSG 入力を置き換えるものではなく、併存させる**前提で使ってください。

## `.paths` フォーマット

可読テキストヘッダ＋1 レイ 1 行の数値行です（`.dose` と同じ様式）。

```
# POKER-PATHS 1.0
model: spent_fuel_cask.FCStd
deviation_mm: 0.5
unit: cm
source: SpentFuel
n_source_points: 3840
n_detectors: 15
materials: 0=VOID, 1=Iron, 2=Polyethylene, 3=Source_Dry
detector: 0 D_side_r130 130 0 230
...
# src det nseg | (mat thick)... | bu_type (bu_mat bu_thick)...
0 1 5 | 3 106.244  1 75.1973  2 18.7963  1 5.63859  0 22.5539 | 2 3 106.244  1 83.5273
```

- 減衰計算には **`|` 区切り 2 番目の生の層構成**（VOID を含む）を使います。
- ビルドアップには **3 番目の縮約後の指定**を使います。層材料は実材質名で書かれ、`equivalent` の解決は POKER 側の YAML ビルドアップノードに委ねます。
- 厚さは cm。mfp 換算はエネルギー依存のため POKER 側で行います。
- 材質名だけを渡し、密度・断面積・ビルドアップ係数の解決は POKER の材料ライブラリに任せます。

57,600 レイで約 4.8 MB。テキストのパース時間は POKER 本体の計算時間に埋もれる規模です。

## 層の縮約規則

POKER のビルドアップは最大 3 層です。トレースで得た層列を次の規則で縮約します。

1. VOID と Air をビルドアップ候補から除外する（減衰には生の層をそのまま使う）。
2. 残った層を線源側から順に、**材質単位**で集計する（同一材質の複数区間が別々の枠を占めないように）。
3. 材質が 3 種でパターンが `Concrete-Iron-Concrete` または `Iron-Concrete-Iron` に一致すれば 3 層を採用。
4. それ以外は、mfp の合計が最大になる 2 材質の組を選ぶ。
5. 残った材質は隣接する採用材質へ **mfp 等価**（幾何厚さではなく `mfp / μ_target`）で繰り込む。
6. 有効な組がなければ mfp 最大の 1 材質で単層とする。

μ は `poker_lib.py` が POKER の減衰係数ファイルから算出します（既定 1.25 MeV、`mu_energy` で変更可）。

繰り込み量は監査値として記録されます。キャスクモデルでは平均 0.57 mfp、最大 3.57 mfp、1 mfp を超えるのは全レイの 13% でした。

## 簡易化の監査（audit_mfp.py）

詳細 B-rep モデルと簡易モデルに**同一のレイ集合**を通し、経路ごとの Σμt を比較します。

```
delta = mfp(簡易) − mfp(詳細)
delta > 0 : 簡易モデルの方が遮蔽が厚い → 線量を過小評価 → 非保守
delta < 0 : 簡易モデルの方が薄い       → 線量を過大評価 → 保守
```

重要なのは、**幾何的な誤差の大きさと線量への影響は別物**だという点です。深い角度でしか効かない形状差は、そもそも寄与の小さい経路にしか乗りません。そのため検出器ごとに、非衝突寄与 `exp(−mfp)/d²` で重み付けした **線量比の推定値**と、**支配経路での Δ** を出します。

蓋外周に R40 のフィレットを入れたキャスクでの実行例:

| 指標 | 値 |
|---|---|
| 影響を受けたレイ | 1,439 / 46,080（すべて非保守側） |
| Δmfp 最大 | 0.875 |
| 線量比（最悪の検出器） | 0.981（1.9% の過小評価） |
| 規制評価点（側面 1m・蓋 1m） | 1.000（影響なし） |
| 支配経路での Δ | 全検出器で 0 |

局所的には 0.875 mfp のずれがありますが、それは全 mfp が 115 に達する経路上の差であり、線量にはほぼ寄与しません。「この簡易化は非保守側だが線量影響 2% 未満、規制評価点では影響ゼロ」と数量で言えることがこのツールの目的です。

## 線源点は POKER から取る

`gen_paths.py` は線源の分割点を**自前で生成しません**。`poker_cui -p` が出力する `input:` セクションの `point_source:`（位置と線源強度補正係数）をそのまま読みます。

```
poker_cui -p -t -s model.yaml          # 分割点を出力
```
```jsonc
{ "poker_summary": "model.yaml.summary", "source_name": "SpentFuel", ... }
```

分割規則を再実装しない理由は、分割座標 `divS`/`divM`/`divN` が相対比率で任意に指定でき等間隔とは限らないこと、`weight` ノードの有無で重みの意味（体積分率か強度分率か）が変わること、`GAUSS_LAST` など分割型が複数あることです。

開発中に等面積分割で代表点を生成したところ、POKER の分割点と食い違いました。r2×φ4×z3 の場合、POKER は半径 13.258 / 39.775 cm・重み 1:3。等面積分割では 37.5 / 64.95 cm・重み均等。**座標も重みも別物**でした。POKER は各軸を分割座標で区切り、代表点を各区間の中点に取り、体積差を重みで補償します。

`source_rcc` による自前生成は検証専用として残していますが、実行時に警告が出ます。実運用では使わないでください。

### 仮想点線源との違い

`.summary` の `pseudo_source_points`（および `path_trace_from_pseudo_source_point`）は分割点ではありません。線源のバウンディングボックスの角 8 点と中心の計 9 点で、分割数を変えても増えません。円筒線源の場合、角の点は線源領域の外側にあります。バウンディングボックスの検証用で、実計算には使われません。

このため **`path_trace` から得られるのは仮想点線源の経路だけ**で、分割点ごとの経路は現状取得できません。幾何処理の照合には点線源（分割なし）を使います。

### サマリー出力量の調整

`thinnedindices` ノードでサマリーの出力件数を指定できます（省略時は既定値）。

| キー | 対象 | 既定 |
|---|---|---|
| `sourcepoint` | 入力パラメータの分割点 | 10 |
| `pseudosourcepoint` | 入力パラメータの仮想点線源 | 10 |
| `detectorgrid` | 入力パラメータのグリッド点 | 10 |
| `detectorevaluation` | 計算出力のグリッド点 | 5 |
| `pathtrace` | `path_trace` の仮想点線源 | 5 |
| `buildupenergy` / `buildupmfp` | 多層ビルドアップ係数の表示数 | 3 / 3 |

全分割点を得るには `sourcepoint` を大きくし、`poker_cui` に `-p` を付けます。

## POKER 本体との突き合わせ検証

**POKER は経路を出力できます。** 検出器に `show_path_trace: true` を指定すると、`.summary` の `result` に `path_trace_from_pseudo_source_point` として、線源点→検出器ごとの (ゾーン, 材質, 通過距離, 区間の始終点座標) が出ます。これはレイトレーサの出力そのものなので、線量から逆算せずに区間単位で直接比較できます。

`compare_poker_trace.py` がこの照合を行います。CAD モデルと POKER の CSG モデルが同一形状であることが前提です。

```powershell
& "C:\Program Files\FreeCAD 1.1\bin\freecadcmd.exe" -c `
  "import sys; sys.path.insert(0, r'<repo>\tools'); import compare_poker_trace as c; c.main(r'<spec>.json')"
```

キャスクモデル（フィレット無しの CSG 等価版）で、点線源 4 点 × 検出器 6 点 = 24 経路を照合した結果:

| 指標 | 値 |
|---|---|
| 材質の並び・区間数の不一致 | **0 / 24** |
| 区間長の差 中央値 | 0.0023 cm |
| 平均 | 0.0100 cm |
| 最大 | 0.0473 cm |
| 完全一致（差ゼロ） | 3 経路 |

残差はすべてテッセレーション由来です。円筒面は多角形で内接近似されるため、偏差 0.5 mm に対して最大 0.5 mm 程度のずれが出ます。実測の最大 0.473 mm はこの上限に収まっており、軸に沿った経路や平面を垂直に抜ける経路では差がゼロになります。**経路の解釈そのものに食い違いはありません。**

裏を返せば、`.paths` 経由の経路は POKER の CSG 経路と厳密一致はしません。受け入れ側は偏差と同程度の差を正常として扱ってください。この差を小さくしたい場合はテッセレーション偏差を下げますが、三角形数と所要時間が増えます。

なお **POKER は `path_trace` の材質名を 10 文字で切り詰めて出力します**（`Polyethylene` → `Polyethyle`）。`Heavy_concrete_FP` / `_IL` / `_T` はいずれも `Heavy_conc` となり区別できないため、比較器では前方一致で扱っています。

## 簡易化の監査（audit_mfp.py）

ある形状を**含むモデル**と**含まないモデル**（あるいは平均化したモデル）に、同一のレイ集合を通して Σμt を比較します。**POKER は呼びません。** 両モデルで線源点・検出器・レイ集合が同じなので、線源強度も換算係数も比を取ると相殺し、Σμt だけで比較できます。CAD モデルを POKER で直接計算する手段がない段階から使えることを狙った設計です。

```
delta = mfp(含まない) − mfp(含む)
delta > 0 : 省略した方が遮蔽が厚い → 線量を過小評価 → 非保守
delta < 0 : 省略した方が薄い       → 線量を過大評価 → 保守
```

検出器ごとに、非衝突寄与 `exp(−mfp)/d²` で重み付けした **非衝突線束比の推定値**（`flux_ratio_estimate`）と、**支配経路での Δ** を出します。

**この比はビルドアップ係数を含みません。** 両モデルの層構成が近ければ B(μr) は比で相殺するという前提ですが、片方だけが厚い層を通る経路ではその前提が崩れます。桁の目安として読んでください。`.paths` が通れば POKER の実計算で確認できます。

80 mfp を超える経路は比較対象から除外します（`saturation_mfp`）。POKER 側でクランプされる飽和領域であり、そこでの Δmfp を評価しても意味がないためです。

### 4 つの事例

キャスクモデルで実際に測った結果です。

| 対象 | 誤差の符号 | 支配経路の Δ | 最悪の検出器での線束比 | 判断 |
|---|---|---|---|---|
| 蓋外周のフィレット R40 | 非保守のみ | 0（全検出器） | 0.981 | 無視してよい |
| 蓋の貫通孔 φ100 | 非保守のみ | 14.7 | 0.00023 | **無視できない** |
| 伝熱フィン（スミアリング） | **両方向** | +0.09 | 0.91〜1.30 | 保守と言えない |
| 吊上げトラニオン φ180 | 保守のみ | −2.26 | 317 | 無視してよい（余裕過大） |

**判断基準は形状の大きさではありません。** 40 mm のフィレットは無視でき、100 mm の孔は無視できず、180 mm のトラニオンは無視してよい。大きさの順序と結論の順序が一致していません。効くのは**その形状が支配経路にかかるかどうか**です。孔は「最も抜けやすい経路」を作るので必然的に支配経路になり、フィレットは稜を掠める浅い角度の経路にしか乗りません。

**周期構造の平均化は別種の近似です。** フィンのスミアリングでは、同じ検出器で Δ が +0.26 と −2.28 の両方に振れます。板の中を長く通る経路と隙間を抜ける経路で符号が反転するためで、**保守性を主張できません**。保守側に倒したいならフィンを省略する方が明快です。

**保守側でも余裕が過大なら見直す価値があります。** トラニオンを省略すると直背後で 317 倍の過大評価になります。安全評価としては問題ありませんが、表面線量を評価するならモデル化した方が実態に近い値になります。

### 密度の上書き

スミアリングのように同じ材質で密度だけを変える場合、CAD 側でソリッドに `PokerDensity`（float, g/cm³）プロパティを設定します。トレーサはこれを読み、μ をライブラリ密度からスケールします。未設定ならライブラリ値です。

新しい材料をライブラリに登録する必要はありません。POKER 側もゾーンの `density` 上書きで表現できます。

### 推定値の妥当性

`flux_ratio_estimate` は B(μr) を 1 と置いた比なので、POKER の実計算とはずれます。トラニオンは円柱で CSG に載るため、同じ体系を POKER でも表現して突き合わせました。

| 検出器 | POKER 実計算 | 監査ツール推定 | 差 |
|---|---|---|---|
| TRU_behind_10cm | 210 | 317 | +51% |
| TRU_behind_1m | 1.022 | 1.028 | +0.6% |
| TRU_edge_r1m_y10 | 1.210 | 1.193 | −1.4% |
| TRU_beside_y30 | 1.107 | 1.097 | −0.9% |
| TRU_above_z30 | 1.027 | 1.042 | +1.5% |
| CTRL_side_1m_z230 | 1.000 | 1.000 | 0 |

**比が 1 に近い領域では 2% 以内**で一致します。「無視してよいか」の判断はこの領域で行われるので、実用上は十分な精度です。

**比が大きく外れる領域では推定が過大**になります。分子・分母の両方に B が掛かるところ、遮蔽が厚い側（分母 = 形状を含むモデル）の B が大きいため、B を含む実計算の方が比が小さくなります。上の例では `B(あり)/B(なし) ≈ 1.51`、すなわち鉄 18 cm の上乗せで B が 1.5 倍になった計算です。

この方向のずれは監査ツールとして望ましい性質です。**影響を過大に見積もる側に外れる**ので、「無視してよい」という判定が保守側に倒れます。

ただし上の比較には条件の不一致が含まれます。CAD 側はトラニオン 4 本・POKER 側は 1 本、CAD 側は 1.25 MeV 単一・POKER 側は Co-60 の 2 群です。差の主因はビルドアップと考えられますが、切り分けはできていません。`.paths` が通れば任意形状で厳密な比較ができるので、そこで再評価します。

## 現状と制限

- 線源点は `poker_cui -p` の出力から取得します（上記「線源点は POKER から取る」）。`source_rcc` による自前生成は検証専用で、POKER の分割規則とは一致しません。
- POKER 側の `.paths` 受け入れは未実装です。監査ツールは POKER の改造なしで使えます。
- 曲面はテッセレーション近似です。偏差 0.5 mm での影響は断面積データの不確かさに比べて桁違いに小さいですが、極端に薄い層を扱う場合は偏差の見直しが必要です。
